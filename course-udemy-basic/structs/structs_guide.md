# Экспорт в структурах Go: заглавная vs строчная буква

Гайд на примере пакета `user` (модуль `example.com/structs`).

---

## Главное правило

В Go видимость определяет **первая буква имени**:

- **Заглавная буква** → идентификатор **экспортируется**, доступен глобально из
  других пакетов.
- **Строчная буква** → идентификатор **приватный** (unexported), доступен только
  внутри своего пакета.

Это правило работает **одинаково** для всего: типов, функций, **полей структуры** и
**методов**.

---

## Часть 1. Поля структуры

```go
package user

type User struct {
	firstName string // строчная → видна ТОЛЬКО внутри пакета user
	lastName  string // строчная → приватная
	birthdate string // строчная → приватная
	createdAt time.Time
}
```

Все поля `User` начинаются со строчной буквы, поэтому из пакета `main` к ним
**нельзя обратиться напрямую**:

```go
import "example.com/structs/user"

u, _ := user.NewUser("Max", "Mustermann", "01/01/1990")

fmt.Println(u.firstName) // ❌ ОШИБКА компиляции:
                         //    u.firstName undefined (cannot refer to unexported field)
```

Если бы поле было с заглавной буквы, доступ был бы открыт:

```go
type User struct {
	FirstName string // заглавная → видно из любого пакета
	lastName  string // строчная → только внутри user
}

u.FirstName = "Max"      // ✅ можно читать и менять снаружи
fmt.Println(u.lastName)  // ❌ всё ещё нельзя
```

---

## Часть 2. Методы

С методами абсолютно то же правило.

```go
func (u *User) PrintUserData() { ... } // Print... с заглавной → экспортируется
func (u *User) ClearUserData() { ... } // Clear... с заглавной → экспортируется
```

Поэтому из `main` их вызывать можно:

```go
u.PrintUserData() // ✅ метод экспортирован
u.ClearUserData() // ✅ метод экспортирован
```

А приватный метод был бы недоступен снаружи:

```go
func (u *User) validate() error { ... } // строчная → приватный

u.validate() // ❌ ОШИБКА: u.validate undefined (cannot refer to unexported method)
```

## Часть 3. Указатель `*User` в мутаторах

Обратите внимание на получатель метода — он стоит с **звёздочкой**:

```go
func (u *User) ClearUserData() { // u *User — указатель
	u.firstName = ""
	u.lastName = ""
	u.birthdate = ""
}
```

`u *User` означает, что метод получает **указатель** на структуру, а не её копию.
Для **мутаторов** (методов, которые меняют поля) это **обязательно**.

### Почему

В Go всё передаётся **по значению** — то есть копируется. Если получатель будет
не указателем, а значением (`u User`), метод получит **копию** структуры и изменит
именно её, а оригинал останется нетронутым:

```go
func (u User) ClearUserData() { // ❌ значение → работаем с КОПИЕЙ
	u.firstName = "" // меняется копия, оригинал НЕ изменится
}

u, _ := user.NewUser("Max", "Mustermann", "01/01/1990")
u.ClearUserData()
u.PrintUserData() // First Name: Max  ← данные на месте, очистка «не сработала»
```

С указателем `u *User` метод работает с **тем же** объектом в памяти, и изменения
видны снаружи:

```go
func (u *User) ClearUserData() { // ✅ указатель → меняем ОРИГИНАЛ
	u.firstName = ""
}

u.ClearUserData()
u.PrintUserData() // First Name:  ← поля действительно очищены
```

### Правило

- **Метод что-то меняет в структуре** (мутатор) → получатель **обязан** быть
  указателем: `func (u *User) ...`.
- **Метод только читает** (как `PrintUserData`) → можно и значение, но указатель
  тоже подходит. Чтобы не плодить копии больших структур и не путаться,
  на практике обычно делают **все методы типа на указателе** — единообразно.

> Указатель и экспорт (заглавная/строчная буква) — это **разные** вещи. Звёздочка
> отвечает за то, *меняется ли оригинал*, а первая буква имени — за то, *виден ли
> метод снаружи пакета*.

## Часть 4. Зачем так делают (инкапсуляция)

Поля `User` намеренно сделаны приватными, а создаётся структура через
**конструктор-функцию** `NewUser` (заглавная буква → экспортируется):

```go
func NewUser(firstName, lastName, birthdate string) (User, error) {
	if firstName == "" || lastName == "" || birthdate == "" {
		return User{}, errors.New("all fields are required")
	}
	return User{
		firstName: firstName,
		lastName:  lastName,
		birthdate: birthdate,
		createdAt: time.Now(),
	}, nil
}
```

Это даёт **инкапсуляцию**: снаружи нельзя создать «битый» `User` с пустыми полями
или подставить произвольный `createdAt` — данные проходят через проверку в
`NewUser`. Снаружи доступны только то, что пакет сознательно открыл: функция
`NewUser` и методы `PrintUserData` / `ClearUserData`.

---

## Шпаргалка

| Имя              | Первая буква | Видно снаружи пакета? |
| ---------------- | ------------ | --------------------- |
| `FirstName`      | заглавная    | ✅ да                 |
| `firstName`      | строчная     | ❌ нет                |
| `PrintUserData()`| заглавная    | ✅ да                 |
| `validate()`     | строчная     | ❌ нет                |

> Важно: правило работает **на уровне пакета**, а не структуры. Внутри пакета
> `user` доступны все поля и методы — и приватные тоже. Ограничение действует
> только для кода **из других пакетов** (например, `main`).
